# هاشم للطيب والعطور — واجهات النظام (React + Vite + Capacitor)

مبنية وفق التحليل المعتمد: Feature-based، Supabase، RTL عربي، جاهزة للتغليف كتطبيق Android/iOS عبر Capacitor.

## التشغيل في 4 خطوات

**1) أنشئ مشروعاً في Supabase** (supabase.com ← New project).

**2) أنشئ قاعدة البيانات** — اختر طريقة واحدة:
- *الأسهل:* افتح **SQL Editor** والصق محتوى `supabase/full_setup.sql` ثم Run (مرة واحدة على مشروع فارغ).
- *عبر CLI:* `supabase link --project-ref <REF>` ثم `npm run db:push` (يطبّق ملفات `supabase/migrations/` بالترتيب).

**3) انشر دالة إدارة المستخدمين** (مطلوبة للإعداد الأول وإنشاء الحسابات):
`npm run fn:deploy` — أو من Dashboard ← Edge Functions ← New function باسم `manage-user` والصق `supabase/functions/manage-user/index.ts`.

**4) ضع مفاتيح الربط في `.env`** (الخطوة الوحيدة المتبقية في الكود):
```
cd apps/web && cp .env.example .env     # ثم عدّل القيمتين
npm install && npm run dev
```
افتح http://localhost:5173 ← ستظهر لك صفحة **«أنشئ حساب مدير النظام»** مرة واحدة، ثم سجّل الدخول وأنشئ باقي المستخدمين من صفحة المستخدمين.

> الواجهة لا تحتاج أي مفتاح سري. استخدم `anon` فقط في `.env`. مفتاح `service_role` يبقى داخل Supabase (الـ Edge Function تأخذه تلقائياً).
> تأكد في Supabase ← Authentication ← Providers أن **Email** مفعّل.

## ملفات قاعدة البيانات (بالترتيب)
مصدر الحقيقة الوحيد هو `supabase/migrations/` (ملفات الترقيع لم تعد مكررة في الجذر). الملف `supabase/full_setup.sql` **مولَّد تلقائياً** منها:
`node scripts/build-full-setup.mjs`
1. المخطط  2. patch_01  3. patch_02 (الاستبدال، مرتجع الشراء، العمولات، الرواتب)  4. patch_03 (الإعداد الأول)  5. patch_04 (التسعيرة)  6. patch_05 (دور الكشك + هوية شاشة الدخول)  7. patch_06 (طلب البضاعة وآخر دخول وسلامة الأكشاك)  8. **patch_07 (النظام المحاسبي)**

## النظام المحاسبي (patch_07)
| الصفحة | المسار |
|---|---|
| الدليل المحاسبي (شجرة الحسابات + إعدادات الترحيل + إقفال الفترة) | `/accounting/chart` |
| القيود اليومية (تلقائية + يدوية + عكس) | `/accounting/journal` |
| دفتر الأستاذ (كشف حساب برصيد جارٍ) | `/accounting/ledger` |
| ميزان المراجعة + مطابقة الدفاتر المساعدة | `/accounting/trial-balance` |
| الميزانية العمومية | `/accounting/balance-sheet` |
| قائمة الدخل (صفحة الأرباح والخسائر) | `/profit-loss` |

**الربط التلقائي:** كل عملية تولّد قيداً مزدوجاً عبر Triggers على جداولها (دون تعديل دوال RPC): المبيعات والمرتجعات والاستبدال، المشتريات ومرتجعاتها ودفعات الموردين، تحصيل العملاء، المصروفات والإيرادات، التالف والجرد، تحويلات البضاعة (مع حسابات ما بين الفروع)، فروق الورديات، تسويات الفروع، **الرواتب** (استحقاق عند الاعتماد ← صرف عند الدفع) وسلف الموظفين، والأرصدة الافتتاحية. كل قيد يحمل `source_type/source_id/source_event` فلا يتكرر ويُتتبَّع لمستنده.
- القيود غير قابلة للتعديل أو الحذف؛ التصحيح بقيد عكسي. والتوازن (مدين = دائن) يُفحص عند إتمام المعاملة.
- حساب طريقة الدفع/نوع المصروف/نوع الإيراد يُحدَّد من شاشاتها، وبقية الأدوار من «الدليل المحاسبي ← إعدادات الترحيل».
- لإضافة عملية جديدة: اكتب دالة `internal_post_xxx(id)` وربطها بـ Trigger عبر `trg_acc_post('internal_post_xxx')`.

## إدارة المستخدمين (Edge Function)
إنشاء المستخدمين وإعادة تعيين كلمات المرور تحتاج مفتاح service_role، لذا تمر عبر دالة:
```
supabase functions deploy manage-user
```
(الملف: `supabase/functions/manage-user/index.ts`). بدون نشرها تعمل بقية صفحة المستخدمين (تعديل الدور والفرع).

## التصميم
الهوية: بني + ذهبي + كريمي (معرّفة في `tailwind.config.ts`). المكونات المشتركة: `StatCard` (عادية / Hero مع اتجاه ورسم مصغّر)، `Panel`، `Sparkline`، `Skeleton`، وأصناف CSS: `.card` `.card-hover` `.seg` `.tile-*` `.fade-up`.

## التسعيرة (دفعات المخزون حسب سعر الشراء)
عند توريد نفس المنتج بسعر مختلف يُنشأ تلقائياً **دفعة سعر** مستقلة (جدول `stock_layers`) في نفس المخزن/الفرع، فتفصل بين مخزون السعر القديم والجديد.
- الصفحة: `/pricing` (قسم صلاحيات جديد: `pricing`) — الدفعات لكل منتج، التكلفة، الهامش، سعر بيع/جملة خاص بكل دفعة، سجل حركة الدفعة، تصدير وطباعة.
- الصرف التلقائي: البيع والتحويل والتالف تُخصم من الدفعات **FIFO** (الأقدم أولاً) أو **LIFO** — من الإعدادات ← المخزون.
- التحويلات تحمل سعر الدفعة إلى الفرع المستلم، والتكلفة في الفواتير تُحسب من الدفعة المباعة فعلياً.
- يلزم تشغيل `supabase/migrations/20260101000400_patch_04.sql` (أو `full_setup.sql` الجديد). الرصيد الحالي يُرحَّل تلقائياً كدفعة «رصيد سابق».
